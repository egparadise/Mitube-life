# 구글 플레이 등록 가이드 + 스토어 등록정보

이 문서는 "마이 튜브" 앱을 구글 플레이(안드로이드 마켓)에 올리는 전체 과정을, 개발을 잘 모르는 분도 그대로 따라 할 수 있게 정리한 것입니다. 크게 두 부분입니다.

- **(A) 절차 가이드** — 계정 만들기부터 심사 제출까지 순서대로.
- **(B) 스토어 등록정보** — 플레이 콘솔 입력 칸에 그대로 복사해서 붙여넣을 한국어 문구.

> **이 앱의 성격 (설문 답을 결정하는 핵심):** 데이터를 회사 서버에 보내지 않고 **내 휴대폰(기기) 안에만** 저장합니다. 유튜브는 **읽기 전용(구독 목록만 조회)** 으로 연결하고, 사용자 정보를 **수집하지도 공유하지도 않습니다.** 이 성격이 뒤에 나오는 "데이터 보안" 설문 답변을 결정합니다.

> **용어 한 줄 정리**
> - **`.aab`** = 플레이에 올리는 설치 꾸러미 파일(안드로이드 앱 번들). `.apk`의 요즘 버전이라고 보면 됩니다.
> - **EAS** = Expo가 제공하는 클라우드 빌드 서비스. 내 컴퓨터에 안드로이드 개발 도구를 깔지 않아도 인터넷에서 대신 `.aab`를 만들어 줍니다.
> - **플레이 콘솔(Play Console)** = 앱을 등록·관리하는 구글의 관리자 웹사이트.

## (A) 절차 가이드

### 1단계. 구글 플레이 개발자 계정 만들기 (1회 등록비 $25)

앱을 올리려면 "구글 플레이 개발자 계정"이 필요합니다. 평생 1번, **미화 25달러(약 3만 원대)** 를 냅니다. 이후 추가 요금은 없습니다.

1. 웹 브라우저에서 **https://play.google.com/console** 로 들어갑니다.
2. 앱에 쓸 구글 계정(지메일)으로 로그인합니다. (앞으로 이 계정이 앱 주인이 됩니다. 개인 지메일보다는 앱 전용으로 하나 만들어 쓰는 것을 권장.)
3. 계정 유형을 고릅니다. 혼자 만드는 개인 개발자면 **개인(Personal)**, 사업자면 **조직(Organization)** 을 선택합니다.
4. **본인 인증(신원 확인)** 정보를 입력합니다. 2026년 현재 구글은 **법적 이름, 주소, 이메일, 전화번호**, 그리고 경우에 따라 **정부 발급 신분증(주민등록증·운전면허증·여권 등) 사진 업로드**를 요구합니다. 화면 안내에 따라 사진을 찍어 올립니다.
5. 안내에 따라 **등록비 $25** 를 신용/체크카드로 결제합니다.
6. 구글이 신원 확인을 검토합니다. **보통 몇 분~며칠** 걸립니다. 승인되면 이메일이 오고 콘솔을 쓸 수 있습니다.

> **⚠️ 아주 중요 (개인 계정만 해당):** 2023년 11월 13일 이후에 만든 **개인** 계정은, 앱을 정식 출시하기 전에 반드시 **비공개 테스트(Closed testing)를 최소 12명의 테스터로 14일 연속** 진행해야 합니다. (원래 20명이었으나 2024년 12월 11일부터 12명으로 완화됨.) 조직(사업자) 계정은 이 요건이 없습니다.
> - "12명 14일"은 단순히 이메일 12개를 넣는 게 아니라, **각 테스터가 참여 링크로 실제 설치·참여한 상태를 14일 동안 끊김 없이** 유지해야 합니다. 도중에 인원이 12명 밑으로 떨어지면 기간이 초기화될 수 있습니다.
> - 이 요건 때문에 아래 4단계에서 개인 계정은 **내부 테스트가 아니라 비공개 테스트**를 씁니다. 계정 유형에 따라 갈라지는 부분을 잘 확인하세요.

### 2단계. EAS로 출시용 설치 파일(.aab) 빌드하기

**2-1. `eas.json`은 이미 준비돼 있습니다 (확인만)**

이 프로젝트의 `eas.json` 파일에는 이미 출시용 `production` 설정이 들어 있습니다. **새로 만들거나 붙여넣을 필요가 없고, 아래 내용과 같은지 눈으로만 확인**하면 됩니다.

```json
{
  "cli": {
    "version": ">= 12.0.0",
    "appVersionSource": "remote"
  },
  "build": {
    "production": {
      "autoIncrement": true,
      "android": { "buildType": "app-bundle" }
    }
  }
}
```

- `"buildType": "app-bundle"` → 플레이용 `.aab`를 만듭니다. (사실 production은 기본이 `.aab`이지만, 명시돼 있어 확실합니다.)
- `"appVersionSource": "remote"` + `"autoIncrement": true` → **버전 번호(versionCode)를 Expo 서버가 대신 기억하고, 빌드할 때마다 자동으로 1씩 올려 줍니다.** 같은 번호로 두 번 올리면 플레이가 거부하는데, 이 설정 덕분에 신경 쓰지 않아도 됩니다.
  - 참고: `appVersionSource`가 `remote`이면 `app.json`의 `versionCode: 1` 값은 **처음 기준점으로만 쓰이고 이후엔 무시**됩니다. 그러니 `app.json`의 버전 숫자를 직접 손댈 필요가 없습니다.

**2-2. Expo 계정으로 로그인**

터미널(명령어 창)에서 프로젝트 폴더로 이동한 뒤 아래를 실행합니다. EAS CLI가 없다면 먼저 설치합니다.

```bash
npm install -g eas-cli
eas login
```

`eas login`을 치면 Expo 계정 이메일과 비밀번호를 물어봅니다. (Expo 계정이 없으면 https://expo.dev 에서 무료로 하나 만드세요.)

**2-3. 안드로이드 출시 빌드 실행**

```bash
eas build -p android --profile production
```

- 아직 이 프로젝트를 EAS에 연결한 적이 없다면, 처음 실행 시 **"이 프로젝트를 당신의 Expo 계정에 새로 만들까요?(Would you like to create...)"** 를 물어봅니다. **Yes** 로 진행합니다.
- 이어서 **"앱 서명 키(keystore)를 EAS가 대신 만들어 관리할까요?"** 라고 물어봅니다. 잘 모르면 **Yes** 를 선택하세요. (이 키를 잃어버리면 나중에 같은 앱을 업데이트할 수 없으니, EAS에 맡기는 편이 안전합니다.)
- 빌드는 클라우드에서 돌아가며 **보통 10~20분**입니다. 끝나면 터미널에 `.aab` 파일 링크가 나옵니다. 그 링크에서 `.aab`를 컴퓨터에 저장합니다. (또는 https://expo.dev 의 내 프로젝트 → **Builds** 에서도 받을 수 있습니다.)

> **참고 (변경 불가 값):** `app.json`의 안드로이드 패키지명이 **`com.favorit.tubeorganizer`** 로 되어 있습니다(현재 그렇게 설정돼 있음, iOS 번들도 동일). 이 값은 출시 후 **절대 바꿀 수 없으니** 빌드 전에 한 번 확인하세요.

### 3단계. 플레이 콘솔에서 앱 만들기

1. **https://play.google.com/console** 에 로그인합니다.
2. **모든 앱(All apps)** 화면에서 오른쪽 위 **앱 만들기(Create app)** 버튼을 누릅니다.
3. 다음을 입력합니다.
   - **앱 이름(App name):** `마이 튜브` (사용자에게 보이는 이름. 나중에 바꿀 수 있음)
   - **기본 언어(Default language):** `한국어 – 한국어(ko-KR)`
   - **앱 또는 게임(App or game):** `앱`
   - **무료 또는 유료(Free or paid):** `무료`
4. 아래 **선언(Declarations)** 의 개발자 프로그램 정책과 미국 수출법 동의 체크박스 2개를 체크합니다.
5. **앱 만들기(Create app)** 를 누릅니다. 앱의 대시보드(Dashboard) 화면으로 넘어갑니다.

### 4단계. 테스트 트랙에 .aab 올리기

정식 출시(프로덕션) 전에 테스트 트랙에서 먼저 올려 검증합니다. **계정 유형에 따라 권장 트랙이 다릅니다.**

- **개인 계정:** 1단계의 **12명 / 14일** 요건을 채워야 하므로 처음부터 **비공개 테스트(Closed testing)** 트랙을 사용하세요.
- **조직(사업자) 계정:** 요건이 없으므로 가장 간단한 **내부 테스트(Internal testing)** 로 빠르게 확인한 뒤 바로 프로덕션으로 가도 됩니다.

**올리는 방법:**

1. 왼쪽 메뉴에서 **테스트 및 출시(Test and release)** → **테스트(Testing)** → **비공개 테스트(Closed testing)**(또는 **내부 테스트(Internal testing)**)를 엽니다.
2. **새 버전 만들기(Create new release)** 버튼을 누릅니다.
3. **앱 번들(App bundles)** 영역에 2단계에서 받은 **`.aab` 파일을 끌어다 놓거나 업로드(Upload)** 합니다.
4. **출시명(Release name)** 과 **출시 노트(Release notes, 이번 버전 변경점)** 를 적습니다. 첫 버전은 `첫 출시` 정도면 됩니다.
5. **다음(Next)** → **저장(Save)** → **검토(Review release)** 순으로 진행합니다.

**테스터 등록 (비공개 테스트일 때):**

1. 같은 비공개 테스트 화면의 **테스터(Testers)** 탭으로 갑니다.
2. **이메일 목록(Email list)** 을 만들어 테스터들의 지메일 주소를 넣습니다. (개인 계정은 최소 12명 필요.)
3. 화면에 나오는 **참여 링크(opt-in URL)** 를 테스터들에게 보내, 각자 링크에서 **테스트 참여(Become a tester)** 를 누르고 플레이에서 앱을 설치하게 합니다. 이 상태를 **14일 연속** 유지해야 프로덕션 신청 자격이 생깁니다.

> **팁:** 테스터 12명을 못 구하겠다면, 가족·지인의 지메일을 모으거나 개발자 커뮤니티에서 서로 테스터를 교환하는 방법이 흔히 쓰입니다. 실제 기기에서 앱을 설치·실행만 해 주면 됩니다.

### 5단계. 앱 콘텐츠 설문 채우기 (개인정보처리방침·데이터 보안·콘텐츠 등급 등)

왼쪽 메뉴 **앱 콘텐츠(App content)** 화면에서 아래 항목들을 하나씩 채웁니다. 각 항목 옆에 **시작(Start)** 버튼이 있습니다.

#### 5-1. 개인정보처리방침(Privacy policy) URL

- **앱 콘텐츠(App content)** → **개인정보처리방침(Privacy policy)** → **시작**.
- 인터넷에 공개된 **개인정보처리방침 웹페이지 주소(URL)** 를 넣어야 합니다. (데이터를 수집하지 않아도 URL은 반드시 있어야 합니다.)
- 방침 웹페이지가 없다면 무료로 만들 수 있습니다: 예) GitHub Pages, Google 사이트도구, Notion 공개 페이지 등에 아래 취지의 글을 올리고 그 주소를 넣으세요.
  > 본 앱은 사용자의 개인정보를 수집·저장·전송하지 않습니다. 유튜브 구독 목록은 사용자의 기기 안에서만 조회·표시되며, 앱 개발자를 포함한 외부로 전송되지 않습니다. 유튜브 연결에는 읽기 전용 권한만 사용합니다. 문의: (이메일 주소)
- 넣은 뒤 **저장(Save)**.

#### 5-2. 데이터 보안(Data safety) 설문 — 이 앱 기준 권장 답변

- **앱 콘텐츠(App content)** → **데이터 보안(Data safety)** → **시작(Start)**.
- 이 설문은 여러 단계로 나뉩니다. 마이 튜브처럼 **아무 데이터도 수집·공유하지 않는** 앱의 권장 답변은 다음과 같습니다.

| 설문 단계 | 화면에 나오는 질문(요지) | 권장 답변 |
|---|---|---|
| 개요(Overview) | 안내 읽기 | 그대로 **다음(Next)** |
| 데이터 수집 및 보안(Data collection and security) | "앱이 사용자 데이터를 수집하거나 공유합니까?" | **아니요(No)** |
| " | "전송 중 데이터가 암호화됩니까?" | 수집이 없으면 이 질문은 보통 나타나지 않습니다. 나오면 유튜브 통신은 HTTPS이므로 **예(Yes)** |
| " | "사용자가 데이터 삭제를 요청할 방법을 제공합니까?" | 수집 데이터가 없으므로 해당 없음/표시되지 않음 |
| 데이터 유형(Data types) | 수집하는 데이터 종류 선택 | **아무것도 선택하지 않음** (빈 상태로 진행) |

- **핵심 판단 근거:** 유튜브 구독 목록은 사용자의 **기기 안에서만** 읽어 화면에 보여줄 뿐, 개발자 서버로 보내거나 제3자와 공유하지 않습니다. 구글 기준에서 "수집(collect)"은 **앱 밖(개발자 서버 등)으로 데이터를 내보내는 것**을 뜻하므로, 기기 내에서만 처리하는 이 앱은 **"수집 안 함"** 이 맞습니다.
- **⚠️ 주의:** 만약 나중에 Firebase, 애드몹(AdMob), Crashlytics, Sentry, 구글 애널리틱스 같은 **외부 SDK(추적/분석/광고 도구)** 를 넣으면, 그 SDK가 수집하는 데이터도 여기에 신고해야 합니다. 현재는 그런 도구가 없으므로 "수집 안 함"이 정확합니다. 나중에 추가하면 이 설문을 반드시 수정하세요.
- 마지막 **미리보기(Store listing preview)** 를 확인하고 **저장(Save)**.

#### 5-3. 콘텐츠 등급(Content rating) — IARC 설문

- **앱 콘텐츠(App content)** → **콘텐츠 등급(Content rating)** → **시작(Start)**.
- **연락용 이메일 주소**를 넣고 약관 동의에 체크한 뒤 **앱 카테고리**를 고릅니다. 이 앱은 게임이 아니므로 **기타 모든 앱 유형(All other app types)** 계열을 선택합니다.
- 이어지는 질문들(폭력성·성적 내용·욕설·도박 등)에 이 앱은 모두 **아니요(No)** 로 답하면 됩니다. (구독 채널을 정리하는 도구일 뿐 부적절한 콘텐츠가 없습니다.)
- **저장(Save)** → 자동으로 계산된 등급 요약을 확인하고 **제출(Submit)**. 한 번에 한국(GRAC)·유럽(PEGI)·북미(ESRB) 등 지역별 등급이 함께 생성됩니다.

#### 5-4. 나머지 필수 설문

같은 **앱 콘텐츠(App content)** 화면에 아래 항목들도 있습니다. 순서대로 **시작** 을 눌러 채우세요.

- **타겟층 및 콘텐츠(Target audience and content):** 대상 연령대를 고릅니다. 아동 대상 앱이 아니므로 **만 13세 이상(성인/일반)** 으로 답합니다. ("아동을 겨냥한 앱인가요?" → **아니요**.)
- **광고(Ads):** 광고가 없으므로 **"아니요, 이 앱에는 광고가 없습니다(No, my app doesn't contain ads)"**.
- **광고 ID(Advertising ID):** 이 앱은 광고·분석용 광고 ID를 쓰지 않으므로 **"광고 ID를 사용하지 않음(No)"** 으로 답합니다. (앞의 데이터 보안·광고 답변과 일관되게 맞춥니다.)
- **앱 액세스 권한(App access):** 유튜브 로그인이 있어야 일부 기능이 보이므로, **"일부(또는 모든) 기능에 특별한 접근이 필요함(All or some functionality is restricted)"** 을 고르고, 심사자가 로그인 없이도 화면을 볼 수 있게 **안내 문구**를 적습니다. 예: "실제 유튜브 계정 없이도 데모 데이터로 분류 기능을 확인할 수 있습니다." (데모 모드가 있으므로 별도 테스트 계정은 필요 없습니다.)
- **정부 앱 / 금융 / 건강 등 특수 카테고리:** 해당 없으면 그대로 **아니요**.

---

### 6단계. 스토어 등록정보(Main store listing) 입력

1. 왼쪽 메뉴 **Grow users** → **스토어 등록정보(Store presence)** → **기본 스토어 등록정보(Main store listing)** 로 들어갑니다. (예전 콘솔에서는 "Grow" 였지만, 현재는 **Grow users** 로 표시됩니다. 앱 아이콘 밑 왼쪽 목록에서 찾으세요.)
2. 아래 **(B) 스토어 등록정보** 의 문구를 각 칸에 복사해 붙여넣습니다.
3. **그래픽(Graphics)** 항목에 아래 이미지를 올립니다. (없으면 먼저 준비해야 저장됩니다.)
   - **앱 아이콘:** 512 x 512 픽셀 PNG (프로젝트의 `assets/images/icon.png` 를 512로 맞춰 활용)
   - **그래픽 이미지(Feature graphic):** 1024 x 500 픽셀
   - **휴대전화 스크린샷:** 최소 2장 (권장 4~8장). 앱 실행 화면을 캡처. (웹 빌드 `npm run web` 화면을 휴대폰 비율로 캡처해도 됩니다.)
4. **저장(Save)**.

> **참고:** 개발자 연락처(이메일 등)는 등록정보가 아니라 **스토어 설정(Store settings)** 페이지에서 따로 입력합니다. 요구되면 그쪽도 채우세요.

### 7단계. 검토(심사) 제출

1. **개인 계정** 이라면 먼저 12명/14일 비공개 테스트 요건을 채운 뒤, 대시보드에서 **프로덕션 액세스 신청(Apply for production access)** 을 눌러 테스트 과정·출시 준비 상태에 대한 질문에 답합니다.
2. 요건이 충족되면 **테스트 및 출시(Test and release)** → **프로덕션(Production)** → **새 버전 만들기(Create new release)** 로 `.aab`를 올립니다. (테스트 트랙에서 검증한 것과 같은 파일이면 트랙 승격으로 처리할 수도 있습니다.)
3. 위 5단계의 앱 콘텐츠 설문과 6단계 등록정보가 모두 **완료(초록 체크)** 인지 대시보드에서 확인합니다. 하나라도 미완료면 제출 버튼이 막힙니다.
4. **검토(Review release)** → **프로덕션으로 출시 시작(Start rollout to production)** 을 누릅니다.
5. 구글 심사는 **보통 며칠(첫 앱은 최대 7일 이상 걸릴 수 있음)** 소요됩니다. 승인되면 이메일이 오고, 플레이 스토어에 앱이 노출됩니다.

> **팁:** 처음에는 프로덕션 **출시 비율(rollout)** 을 100%가 아니라 20% 정도로 시작해 문제가 없으면 올리는 "단계적 출시(Staged rollout)" 를 쓸 수 있습니다. 첫 출시라면 그냥 100%로 해도 무방합니다.

마이 튜브은 내 유튜브 구독 채널을 내가 만든 카테고리로 자동 분류하고 깔끔하게 정리해 주는 앱입니다. 구독 목록이 수십, 수백 개로 늘어나 어디에 무엇이 있는지 찾기 어려웠다면, 마이 튜브으로 한눈에 정돈해 보세요.
